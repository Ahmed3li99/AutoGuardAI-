## Key decisions
- **One contract for all sources.** Validation, replay, analysis, history and reports only see
  `NormalizedSession`. A future adapter plugs in as another `VehicleDataSource`.
- **Provenance travels with the data.** `DataOrigin` (recorded / synthetic / live_obd) and `TimeBasis`
  (absolute / relative_recorded / synthetic_clock) live in the metadata, every alert row, every CSV
  row, the PDF header and the UI banner. A SQL `CHECK` constraint rejects unknown origins.
- **Missing means missing.** Absent signals are absent columns. Impossible values become NaN and are
  counted. Gaps longer than 3 s stay NaN and are masked by models. The UI shows `N/A`.
- **No GUI freezes.** File reading, analysis and PDF generation run in `QThreadPool` workers. Replay
  ticks every 100 ms and plots keep at most 3,600 rows.
- **Offline by construction.** HF offline env vars are set at start-up. MOMENT loads with
  `local_files_only=True` from bundled files. There is no network code in the app.
- **Paths.** `core/paths.py` resolves bundled resources (`sys._MEIPASS` when frozen) separately from
  the writable user dir `%LOCALAPPDATA%\AutoGuardAI` (DB, logs). `AUTOGUARD_HOME` overrides it.

- **Explanations are templates, not generated text.** `ai/explain.py` groups overlapping alerts into
  findings and fills fixed Arabic/English templates with measured values (actual, expected, typical
  range, duration, speed context). Nothing is generated by a language model.
- **Language switch** rebuilds the main window. Arabic sets Qt's right-to-left layout direction.
- **Thread safety.** Workers report back only through bound methods of QObjects that live in the GUI
  thread, so the queued connections run on the GUI thread (fixed after a plain-closure callback was
  found running on the worker thread).
- **v0.3 additions.** `ai/consistency.py` runs after the rules as a fifth method (data plausibility,
  thresholds from 129 real trips). `ai/explain.py` labels each finding `car` or `data`.
  `ai/personal.py` adapts the base expected-vs-actual model per vehicle profile; adapted models are
  stored in `%LOCALAPPDATA%\AutoGuardAI\vehicles\<id>\` (hash-checked like the base artifacts).
  `ModelRegistry(vehicle_id=…)` picks the personal model only for trips of that car.
  `ai/scenarios.py` runs injected faults and "what if normal?" counterfactuals on copies of a trip
  (labelled synthetic, never saved). UI: `app/pages/cars_dialog.py`, `app/pages/lab_dialog.py`.
  DB migration v2 adds `sessions.is_reference` and `vehicles.model_json`.
